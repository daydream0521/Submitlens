## 1. 自动预检

在已确认、非 stale 的要求和当前选定成果上执行。保留「已有证据」与「验收通过」的区分。仅实现下面五种自动检查：

1. **文件存在**：必交要求无有效选定成果时不通过。
2. **文件格式**：使用已确认 `extension` 约束；报告实际/要求格式。单靠扩展名无法证明文件内容真实时，不额外宣称内容已验证。
3. **PDF 页数**：使用 `pypdf` 读取真实页数，比对明确的上限/下限/区间。
4. **MP4 时长**：使用一种成熟、轻量且可复现的元数据读取方案（优先纯 Python；必要时在 README 说明系统依赖），报告实际秒数/格式化时长与要求范围；文件损坏需报告读取异常。
5. **文件数量**：对当前要求已选定的不重复成果计数；**只有原文指明需要几份文件时才能自动判断**。如「至少三组 Prompt 迭代」指材料内容而非文件数量，必须交给人工复核。

具体阈值一律来自用户已确认的 `constraints`。目前 `Constraint.value` 是自由文本（例如「5–8 分钟」「不超过 30 页」），只实现本阶段已有样例所需的清晰中文数字/单位解析；解析不了时标记「待复核」，**不得猜默认值，也不得把解析失败当不符合要求**。

每个检查结果在 UI 显示：检查项、实际值、要求值、原文依据、检查时间、结果；错误只显示具体原因和下一步操作。不增加通用规则 DSL、抽象合约层或无必要的校验框架。

## 2. 人工复核与状态

- 对 `needs_manual_review`、`content` 类型约束以及无法自动判断的真实内容项提供「未复核 / 人工确认符合 / 人工确认不符合」，可选备注。
- **人工复核不得覆盖明确的自动检查失败**。综合状态：有失败或必交成果缺失→「不通过」；无失败但仍需复核/存在读取异常→「待复核」；适用自动检查全部通过且必要人工复核完成→「通过」。建议项不改变必交总体判定。
- 每个结论标明「系统检查」或「人工确认」，不展示假置信度；复核结果与项目状态刷新后仍保留。
- 编辑要求中的检查条件、切换选定成果、替换或删除成果、取消关联时，旧自动结果必须失效，相关人工复核不得无条件沿用。沿用阶段三现有内部文件 UUID 和关联表，不新增文件 hash 或复杂版本历史。
- 当要求存在多个候选文件时，**以当前选定文件为准**，不能因为未选定的旧视频失败导致最终要求失败；数量约束按选定集合计数。
- 草稿或 stale 要求不参与正式验收。首次打开没有检查结果的项目应显示待检查，而不是默认通过。
