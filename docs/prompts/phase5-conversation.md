# SubmitLens｜阶段五 Codex 执行计划

## 目标与起点

基于 `daydream0521/Submitlens` 当前 `main`（审查时 `9f31b54`）开发，优先保留本地已有的后续提交，不强制 reset。先读取 `docs/PRD.md`、`docs/UI_COPY.md`、`docs/ACCEPTANCE.md`、`docs/citation-disambiguation.md`，再看现有的 `backend/app/main.py`、`backend/app/checks.py`、`backend/app/citations.py`、`frontend/src/Artifacts.tsx`、`frontend/src/Requirements.tsx` 和 `frontend/src/main.tsx`。

本阶段目标：**从已确认要求、选定成果和已有验收结果，生成真正可用的 ZIP 交付包及 Markdown 验收报告；修改后能提示重新导出；用户能顺畅到达交付中心。**

## 任务 1：交付中心（P0）

1. 新增项目内「交付中心」页面，并接入当前 `#project=<id>&view=...` 导航；不能改变已有任务页和成果验收页行为。
2. 复用当前 `/requirements`、`/artifacts`、`/checks` 数据，不复制预检计算逻辑。按已确认的必交要求展示 **通过 / 不通过 / 待复核 / 待检查**；未确认及 `stale`、`source_issues` 的要求单独提示「待处理」，不能冒充通过或从视野中消失。
3. 默认勾选当前各要求**已选定**的实际提交文件，去重显示；允许用户自行勾选/取消项目文件库中的其他文件。显示文件原名、大小、关联要求和导出目录预览。没有已选定文件时允许用户自行选择已有材料。
4. 交付预览优先显示缺失文件、失败项和待复核项，用户能直接回到成果验收定位并处理。**不因不通过/待复核禁止导出**。
5. 导出按钮应下载真实 ZIP 文件。不存在可交付材料时至少能导出真实报告，但界面明确表明材料为空。

## 任务 2：ZIP 与验收报告（P0）

1. 后端新增最少量的导出 API（例如 `POST /api/projects/{id}/export`）；入参为用户本次选择的 artifact ID 集合。导出目录预览优先在前端基于已有接口生成，不另建预览 API。仅能获取当前项目所属文件，跨项目 ID 必须拒绝。
2. ZIP 结构固定且导出前可预览，如 `materials/...` + 根目录 `submission_report.md`。原始文件字节不变，名称保留；同名文件不会覆盖；每个 artifact 只打包一次；ZIP 条目路径安全。
3. 大视频可能达到 1 GB：ZIP 在磁盘临时文件中生成并流式发送，不把全部素材读入 RAM。成功与失败都清理临时文件；不得遗留堆积的导出副本。
4. Markdown 报告至少包括：项目名与生成时间、任务来源、全部正式要求及必交/建议、原文出处、当前验收状态、选定成果对应关系、自动检查的实际值/目标值/结果/时间、人工复核标记及备注、未解决项。
5. 报告显式区分 **「验收选定文件」** 与 **「实际打包文件」**。用户在导出时取消某个必交证据文件，应标出「验收关联证据未包含在本次 ZIP」，不能只展示原先的「通过」而造成误导。对尚未确认、出处有歧义、原文变更的条目，列在待处理区，不给它们自动通过结论。
6. 不重新调用 LLM、不修改用户成果、不自动提交学校或竞赛平台。

## 任务 3：导出后变更提示（P0）

1. 首次成功导出后记录最少量的状态（如项目最近导出时间 + 后续变更标记）；**不增加文件哈希、完整快照、事件总线或版本历史**。
2. 现有操作中会改变本次材料/报告的行为：修改任务说明或正式要求、成果上传/替换/删除、选定/取消选定、人工复核、重新预检。如果这些操作发生在导出后，界面显示 `材料已更新，请重新导出`。
3. 在用户重新成功导出后清除该提示；页面刷新和后端重启后仍能反映这一事实。不影响现有证据失效和自动重检行为。
4. 仅上传未选定的候选文件，且不改变本次交付选择及报告内容时，不标记旧导出过期；不为所有可能的编辑增加复杂事件架构。

## 任务 4：最小流程衔接（P0）

1. 要求确认成功后，为用户提供一个明显的 `去上传成果` 入口，跳转现有成果验收页。
2. 成果验收页提供 `交付中心` 入口，直接到新页面。导出页的失败/待处理项能返回相应验收或任务页。
3. 不重构全站布局、不增加营销文案；界面符合 `docs/UI_COPY.md` 的简短文案约束。

## 任务 5：现有 AI 引文消歧只做回归（P0）

当前 `backend/app/citations.py` 与 `docs/citation-disambiguation.md` 已实现基于章节的引用定位、歧义来源候选、待处理草稿和禁止整单确认未决条目；仓库记录：原始 DeepSeek 响应**离线回放已得到 5 条可编辑待处理草稿**。不要重复开发，不要把它写成尚未实现。

- 使用现有 `data/real-extract-response.json` 和测试任务原文（若本机存在）做离线回归；确认无误引用省赛/国赛、待处理条目无法被误确认。
- 无数据文件时依靠仓库现有 `backend.check_citations` 回归，报告「真实离线文件未复测」，不要编造结果。
- 本阶段不发付费 LLM 请求，不读取、输出或提交 API Key。只有出现**新的可复现失败**时才做最小范围修改。

## 必须完成的验收

- **完整业务链**：创建项目 → 导入/粘贴要求 → 确认清单 → 上传/选定实际成果 → 预检/人工复核 → 交付中心 → 下载 ZIP 与报告；刷新后相关数据仍在。
- **真实 ZIP**：用真实 PDF、MP4、Markdown 构造材料；检查归档条目、解压后的文件字节与原文件一致；同名不同内容不覆盖；相同文件关联多项要求只打包一次。
- **报告真实**：不通过、待复核、人工已确认、检查异常和未确认来源各有正确记录；故意取消一项必交文件后报告不谎称本次 ZIP 已包含该证据。
- **变更**：导出 → 替换选定文件/更改复核/编辑要求 → 提示旧导出已过期 → 重新导出后提示清除。重启后结果仍正确。
- **异常**：不存在/跨项目 artifact ID、磁盘素材缺失、ZIP 创建失败不产生错误成功提示或残留临时文件。
- **回归**：阶段 1–4、`backend.check_citations`、前端类型检查、生产构建、现有 Playwright 测试通过；新增少量针对上述真实行为的后端/浏览器用例。报告实测命令、结果和未覆盖项，不声称未执行测试通过。
