# SubmitLens — UI 文案与呈现约束 V1.0

## 1. 核心判断

每条用户可见文本提交前做两次删除测试：

1. **删掉后是否影响理解、决策或完成操作？** 不影响就删除。
2. **保留后是否削弱专业感、让界面像 AI 生成的模板产品？** 是则改成具体信息或删除。

文案只做四件事：**标识对象、说明当前状态、呈现检查依据、引导下一步操作**。不用营销语、空洞价值宣言、技术炫耀和防御性废话。

## 2. 默认字数预算（设计约束，可按实际布局微调）

| 位置 | 初始限制 | 备注 |
|---|---:|---|
| 主导航/标签页 | ≤ 6 个汉字 | 例：任务、成果、交付 |
| 页面主标题 | ≤ 12 个汉字 | 例：交付中心 |
| 主要按钮 | ≤ 8 个汉字 | 例：上传文件、开始预检 |
| 字段名/状态标签 | ≤ 8 个汉字 | 例：待复核、文件格式 |
| 列表项标题 | ≤ 16 个汉字 | 保留任务的关键名词 |
| 简短辅助说明 | ≤ 30 个汉字 | 一句，必要时才出现 |
| 错误提示 | 优先 ≤ 40 个汉字 | 必须包含可行动的信息 |
| 检查详情 | 不限制真实值和原文片段 | 依据和要求必须完整，不截断真实约束 |

字数预算不应用于裁剪用户原始文档、文件名或关键证据。长文件名允许视觉截断，但详情与导出仍保留完整名称。

## 3. 推荐文案清单（前端可直接使用）

| 场景 | 使用 | 避免 |
|---|---|---|
| 首页空状态 | 暂无项目 / 新建项目 | 开启你的智能交付管理之旅 |
| 新建类型 | 竞赛 / 课程 | 选择你的专属学习成长空间 |
| 任务输入 | 粘贴文本 / 上传文件 | 利用 AI 释放非凡生产力 |
| 提取过程 | 正在整理要求 | AI 正在深度理解你的复杂任务场景 |
| 提取完成 | 已整理 8 项要求 | 成功构建智能化交付知识体系 |
| 确认 | 确认清单 | 我已认真审阅且完全理解所有内容 |
| 文件上传 | 上传成果 / 从文件库选择 | 开始将你的创作成果赋能 |
| 预检 | 开始预检 | 一键全方位智能质量守护 |
| 状态 | 通过 / 不通过 / 待复核 | 质量优秀 / 存在潜在风险请留意 |
| 检查异常 | 无法读取视频时长，请换文件 | 由于复杂外部原因暂无法对该对象进行完整分析 |
| 失败明细 | 视频 09:21，超出上限 01:21 | 该视频可能无法完全满足相关赛事规范 |
| 人工状态 | 人工确认通过 | 系统已智能认证该作品完全合格 |
| 导出 | 导出材料 | 打造你的终极无忧交付体验 |
| 修改后 | 材料已更新，请重新导出 | 为保证万无一失建议您审慎检查所有相关材料 |

## 4. 页面文案层级

### 页面一：项目与要求

- 一级标题：`我的项目` / `任务要求`
- 核心按钮：`新建项目`、`粘贴文本`、`上传文件`、`整理要求`、`确认清单`
- 要求卡片：**材料名称 + 约束标签 + 状态**。只有用户点开才显示原文位置、编辑及完整条款。
- 有 AI 误提、漏提时：直接提供 `编辑`、`删除`、`添加要求`，不需要写“AI 可能有错，请仔细核对每一项”。

### 页面二：成果验收

- 一级标题：`成果验收`
- 核心操作：`上传成果`、`从文件库选择`、`设为提交文件`、`开始预检`、`重新检查`
- 主要状态：`通过`、`不通过`、`待复核`。
- 检查详情固定呈现：`实际`、`要求`、`依据`；必要时呈现 `检查时间` 和失败原因。
- 复核操作：`符合`、`不符合`、`暂不复核`；结果注明 `人工确认`。

### 页面三：交付中心

- 一级标题：`交付中心`
- 摘要：`已通过 N`、`不通过 N`、`待复核 N`
- 核心操作：`选择文件`、`预览目录`、`导出 ZIP`
- 未完成时允许导出；展示具体未解决项，禁止空泛恐吓式警告。

## 5. 视觉规范只规定方向，不提前装饰

- 清晰的三层信息结构：项目概览 → 要求/文件列表 → 详细检查结果。
- 优先用排版、留白、状态分组和真实数据建立视觉层次；避免无意义渐变、巨大宣传语、堆叠胶囊标签。
- 每种颜色承载一种状态语义，图标辅助但不能单靠颜色区分。
- 分组卡片和状态比例条可以在 P1 打磨；P0 保证信息准确且可用。
- Loading、空状态和错误反馈应有明确内容，但一律简短。

## 6. Codex 文案验收

每新增一处用户可见文本时，检查：

- [ ] 是否直接关系到当前操作或判断？
- [ ] 是否重复了标题、图标、按钮已经表达的意思？
- [ ] 是否存在“AI赋能、无忧、智能化、专业级、全方位、革命性”等空话？
- [ ] 是否把不能自动验证的内容说成系统已验证？
- [ ] 是否存在没有行动价值的“仅供参考”“请谨慎”“不代表”等辩护句？
- [ ] 是否保留了完整客观约束与实际检查数据？

前五项如存在问题，优先删除或改写；最后一项必须保留。产品界面不得用营销文案掩盖功能缺失。
