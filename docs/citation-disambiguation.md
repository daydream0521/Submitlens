# 重复章节引用消歧修复

2026-11-06。用户要求离线分析已存 DeepSeek 响应、保留 Pydantic 与原文追溯、用章节和片段消歧、未决草稿不阻断有效要求，并授权推送此前提交。

## 实际原因与行为

真实赛道 Markdown 的省赛/国赛均有代码仓库、演示视频、技术文档等同名章节。已存响应的 source_ref 合并两阶段的范围，短引文也在两阶段重复；不能凭匹配顺序决定来源。

后端从现有 task_segments 的 Markdown 标题建立实际章节上下文，用精确引文匹配验证候选。精确片段候选必须确实包含引文；范围候选只筛选真实范围内且章节名对应的匹配。章节候选和已定位要求的上下文用于消歧；如果候选章节与引文不符，不回退到其他章节。约束引用不会因为其他章节恰有唯一同文就自动归入当前要求。

Pydantic RequirementInput/Constraint 保持不变；未决问题作为已有要求 JSON 的 source_issues 元数据保存，source_ref 留空，提供实际候选片段和章节。提取成功返回可编辑草稿，整单确认跳过未决条目；不阻断其他有效要求。界面可选择出处并编辑保存，后端再次核对。拆分/合并未决条目也重新定位，不绕过问题标识。

Prompt 新增：不同赛事阶段分开返回；优先引用实际交付条款/完整表格数据行，避免章节标题、孤立数字、推荐选题、评分及办理事项；只返回单个真实候选片段编号，不合并或编造范围。本次没有重新调用模型，不能据此声称新 Prompt 的真实模型效果已测。
